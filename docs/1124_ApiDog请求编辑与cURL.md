# ApiDog 请求编辑与 cURL

## 请求里的变量

之前「默认」代表当前全局环境，「变量」用来编辑该环境。现在变量跟着单个请求走。在地址填 `http://111/{hostname}/ping` 后，请求下方会出现 `hostname` 输入框。同一个请求改值就能重发，新建请求有自己的变量。URL 中单层花括号的值按地址中的一段编码，例如 `node/a` 会变成 `node%2Fa`。旧的双花括号依然可以回放，例如把整段基地址填入 `{{baseUrl}}`。

## 编辑请求

请求头和查询参数分两列填名称和值。认证可以选 Bearer Token、Basic 用户名和密码、API Key 请求头。认证页生成 Authorization 等请求头，如和手动填写的头同名，界面提示冲突。请求体保留文本编辑，适合直接粘贴 JSON。

右侧默认显示 cURL，随请求变化更新。预览、复制和发送用同一个请求构建结果，认证信息会出现在生成的命令里。发送后显示响应，可随时切回 cURL。

「导入 cURL」把文本拆为方法、URL、查询项、请求头、认证和文本请求体。导入只解析文本。支持常见的浏览器复制命令，包括换行续写、常用数据参数和跟随重定向，不调用 Shell，不读取命令里引用的文件。不支持的选项明确报出，导入失败时保留当前请求。

## 历史兼容

已有历史继续可读，旧请求头从文本拆成名称和值。打开旧历史时，将当时环境里仍可用的值填进该请求的变量。新历史记录请求模板和变量值。认证页填写的密钥只保留本次运行，重新打开应用后可补填。直接填进 URL、请求头或请求体的内容会随历史保存。
