# ApiDog 桌面版设计

## 为什么做桌面版

ApiDog 面向个人接口调试。请求从当前 Mac 发出，能访问这台机器通过 VPN 或内网接入的地址，本机服务也可以直接填 `localhost`。远程网页版适合团队共享，但目标接口得从服务器访问，还需要部署服务和管理使用权限。

第一版做成 macOS 原生应用。SwiftUI 是 macOS 提供的界面框架，URLSession 负责发送 HTTP 请求。用户可以把应用从 DMG 安装镜像拖到「应用程序」。源码放 GitHub，个人调试数据留在 Mac。

## 一次调试怎么操作

1. 选择 GET、POST 等请求方法，填 URL。需要替换的部分用 `{变量名}` 表示，在当前请求的「变量」页填值。
2. 在请求区域按名称和值填查询参数、请求头或认证字段。请求头是随请求发出的字段，例如 `Content-Type` 告诉服务端正文格式。
3. 右侧预览并复制 cURL 命令，也可以把已有命令导入编辑。发送后可看状态码、耗时、响应头和正文。
4. 从侧边栏打开历史，恢复请求和响应摘要。

## 工作台界面

深色底搭配薄荷绿主操作，地址栏固定在最上方，请求方法用颜色和文字区分。宽窗口让请求编辑和响应并排，窄窗口改为上下排布，尽量给结果留空间。

顶部使用工作台自己的工具栏。左侧是应用标识，中间可以拖动窗口，右侧放 cURL 导入、最小化、全屏和关闭。AppKit 是 macOS 的窗口管理框架，按钮外观由 ApiDog 绘制，窗口操作交给 AppKit 执行。

cURL 导入和清空历史确认放在窗口内的深色弹层。弹层打开时，焦点留在弹层中，按 Esc 可取消。清空历史需要单独确认，回车默认取消。

请求方法和认证通过工作台样式的下拉列表直接选择，当前项带勾选标记。可用方向键移动、回车选择，也可点空白处或按 Esc 关闭。历史操作使用同一套下拉样式，复制地址放在每条历史上。

左侧历史可按地址、方法和状态码搜索。发送后可以取消，取消的请求不进入历史。响应面板集中显示状态码、耗时和大小，可直接复制当前选中的正文或响应头。变量、请求头和认证字段在当前请求内编辑。

## 请求目录和历史

左侧有独立的「请求目录」和「请求历史」。目录支持创建一级分类，分类可以折叠。目录加号里的「新建请求」会先填写名称和分类，创建后就能从目录打开。调好的请求也可用地址栏旁的「保存」收进目录，已有请求可以在保存时改名或改分类。

发送只追加历史，保存才更新目录。点历史可把某次请求载入工作台再编辑。历史菜单始终可打开，清空历史单独确认。清空历史和删除目录里的单个请求互不影响。

## 数据放在哪里

ApiDog 把调试数据保存在 `~/Library/Application Support/ApiDog/workspace.json`。JSON 是普通文本，适合这一版的数据量。更新时先写完整副本再替换旧文件，保存请求目录并保留最近 100 次请求，正文最多读取 256 KiB。当前窗口可查看完整的已读取响应，历史里保留请求模板、请求内变量、时间、状态码和耗时，响应正文与响应头只在当前窗口显示。

目录请求的认证凭证在本机加密保存，解密密钥由当前账号的文件权限保护。旧版的钥匙串密钥可在应用内迁移一次。请求历史会清除认证凭证，直接写入 URL、普通请求头和正文的数据会随历史明文保存。旧请求和历史仍可打开。

## 第一版边界

支持 HTTP 和 HTTPS、常用方法、文本请求体、请求内变量及本地历史。可按请求选择是否跟随重定向。二进制响应显示类型，不提供下载。暂不做账号、云同步、团队协作、自动化测试或接口文档。
