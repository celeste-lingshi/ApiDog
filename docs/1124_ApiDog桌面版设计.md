# ApiDog 桌面版设计

## 为什么做桌面版

ApiDog 面向个人接口调试。请求从当前 Mac 发出，能访问这台机器通过 VPN 或内网接入的地址，本机服务也可以直接填 `localhost`。远程网页版适合团队共享，但目标接口得从服务器访问，还需要部署服务和管理使用权限。

第一版做成 macOS 原生应用。SwiftUI 是 macOS 提供的界面框架，URLSession 负责发送 HTTP 请求。用户可以把应用从 DMG 安装镜像拖到「应用程序」。源码放 GitHub，个人调试数据留在 Mac。

## 一次调试怎么操作

1. 选择 GET、POST 等请求方法，填 URL、请求头和正文。请求头是跟随请求发送的字段，例如 `Content-Type` 用来告诉服务端正文格式。
2. 按环境保存变量。比如把地址填成 `{{baseUrl}}/users`，可以切换本地和测试环境。URL、请求头值和正文使用同一种占位符。变量值按原文替换，需要转义时，在变量值中填好。
3. 发送后显示 HTTP 状态码、耗时、响应头和正文。JSON 是接口常见的文本格式，能识别时会缩进展示。
4. 从侧边栏打开历史，恢复当时输入的请求和响应摘要。再次发送会用当前所选环境重新替换变量。

## 工作台界面

深色底搭配薄荷绿主操作，地址栏固定在最上方，请求方法用颜色和文字区分。宽窗口让请求编辑和响应并排，窄窗口改为上下排布，尽量给结果留空间。

顶部使用工作台自己的工具栏。左侧是应用标识，中间可以拖动窗口，右侧放环境、变量、最小化、全屏和关闭。AppKit 是 macOS 的窗口管理框架，按钮外观由 ApiDog 绘制，窗口操作交给 AppKit 执行。

环境编辑和清空历史确认放在窗口内的深色弹层。弹层打开时，焦点留在弹层中，按 Esc 可取消。清空历史需要单独确认，回车默认取消。

请求方法和环境通过工作台样式的下拉列表直接选择，当前项带勾选标记。可用方向键移动、回车选择，也可点空白处或按 Esc 关闭。历史操作使用同一套下拉样式，复制地址放在每条历史上。

左侧历史可按地址、方法、状态码和环境搜索。发送后可以取消，取消的请求不进入历史。响应面板集中显示状态码、耗时和大小，可直接复制当前选中的正文或响应头。环境管理把环境列表和变量列表并排，方便来回切换。

## 数据放在哪里

ApiDog 把调试数据保存在 `~/Library/Application Support/ApiDog/workspace.json`。JSON 是普通文本，适合这一版的数据量。更新时先写完整副本再替换旧文件，保留最近 100 次请求，正文最多读取 256 KiB。当前窗口可查看完整的已读取响应，历史里保留请求模板、环境名、时间、状态码和耗时，响应正文与响应头只在当前窗口显示。

环境里的变量及历史请求模板会以明文保存在本机。需要临时使用 Token 时，可以在环境管理里勾选「仅本次运行」，并在请求头使用变量占位符。关闭应用后要重新填该值。清空历史会移除历史请求，环境可单独编辑。

## 第一版边界

支持 HTTP 和 HTTPS、常用方法、文本请求体、环境切换及本地历史。直接展示重定向状态与 Location 响应头，由使用者决定是否发起下一次请求。二进制响应显示类型，不提供下载。暂不做账号、云同步、团队协作、自动化测试或接口文档。
